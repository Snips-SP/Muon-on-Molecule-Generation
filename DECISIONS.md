## Notes

- **D3:** The LR/WD transfer test is weak for the AdamW group, because it holds only ≈ 0.5% of the parameters (`PLAN.md` L3). D19 measures how much the AdamW LR matters.
- **D4:** Replaced by D12; its proposal (both optimizers without compile first, then one run with compile) became runs 2 and 3 of D12.
- **D5:** Proposed, not yet confirmed: also log tokens seen (needed for the epoch view) and wall-clock time (hardware-specific). → Confirmed 2026-10-15 (D29).
- **D6:** This is our own principle, not the paper's: Liu et al. 2025 tuned only AdamW and reused its settings for Muon.
- **D9:** A ~2.2M model on full MOSES is ≈ 6·10¹⁴ FLOPs (own estimate), below the fitted range, so the rule is applied slightly outside the range it was tested on. How it applies to the smaller data scales is still open (`PLAN.md`, O1).
- **D10:** Comparisons are only between our own REF runs, not with Moonshot's numbers.
- **D12:** Why `torch.optim.Muon` can replace the script's Muon (code comparison, own reading, 2026-10-11): both use the same Newton–Schulz (bf16, same coefficients), the same decoupled weight decay with the unadjusted LR and the same match_rms_adamw scaling; torch's momentum buffer is an EMA (lerp), which only rescales the update by (1 − μ), and Newton–Schulz normalizes that away. Confirmed by runs 2 and 4 (≤ 0.01% train-loss difference over 100 steps).
- **D17:** Better justification for untied embeddings (agreed 2026-10-12): stays close to the Llama-style setup (D1) and to Liu et al. 2025, who list embeddings and LM head as separate AdamW parameters (my reading; the paper does not say "untied" explicitly), at a cost of ≈ 7.7k parameters (my calc, d = 256); it also avoids deciding which update rule a shared matrix gets. Note: the REF toy model was tied (`tie_word_embeddings=True`).
- **D24:** Placeholders `warmup_frac` 0.05 and `min_lr_ratio` 0.1 accepted as starting values (2026-10-15); still own choices without a source (O3, O4).
- **D38:** An ablation changes exactly one setting of the reference run and keeps data, schedule and seeds equal. A1–A3 reuse the best LR from SWEEP. A4 needs its own small LR sweep, because `original` takes 0.18–0.31× smaller steps than `match_rms_adamw` at the same LR (`scripts/opt_report.md`, check 4). Batch size, data scale, tokenization and OOD are not ablations: they change several things at once or need their own LR sweeps.
